# 공격대 반복 등록과 삭제 · 0.3.2

2026-11-14. 자동으로 끝없이 늘어나는 반복 규칙 대신, 미리 확인한 유한한 날짜들을 한 번에 저장한다.

## 등록

달력의 **일정 추가 → 공격대 반복 등록**에서 이름·분류·시작 날짜·등록할 주 수·반복 간격을 정한다. 월요일20:00, 일요일18:00처럼 요일마다 시각을 다르게 지정한다. 평일/주말 선택과 공통 시각 적용도 제공한다. 좁은 창에서는 기본 / 요일·시각 / 미리보기 탭을 사용하며 등록/닫기는 하단에 유지한다.

등록 범위는 시작 날짜 이상, 시작 날짜 + 주 수×7일 미만이다. 각 요일의 첫 날짜는 시작 날짜 이후의 첫 해당 요일이다. 이후에는 지정한 주 간격씩 증가한다. 예: 11월14일 시작, 4주, 매주 월·일이면 11월15일~12월7일의8개를 생성한다. 2주 간격이면 각 요일을14일마다 등록한다. 주 수는 생성 횟수가 아닌 전체 기간이다.

시각은 한국 시간(UTC+09:00), 분 단위다. 해외 PC의 현지 시간대와 무관하다. 시작/끝 요일이 같거나 연말·윤년을 통과해도 날짜 계산을 사용한다. 미리보기에는 날짜·요일·시각·중복 제외·과거 시각 개수를 표시한다. 과거 일정은 금지하지 않으며 지난 알림을 소급 발송하지 않는다.

## 검증과 저장

- 제목1~80자, 메모 최대1000자, 요일1~7개, 각 요일의 유효한 HH:mm 또는 H:mm 시각이 필요하다.
- 등록 기간과 간격은1~52주, 날짜는2020~2100년, 총 로컬 일정은2000개까지다. 최대364개를 한 번에 계획한다.
- 같은 프로필·개인 일정 종류·분류·앞뒤 공백을 제거한 제목·정확한 시각이 모두 같으면 중복으로 제외한다. 이름이 비슷한 다른 공대나 다른 시각은 합치지 않는다.
- 저장 직전에 최신 상태로 재검증한다. 미리보기 뒤 분류 삭제·기존 일정 추가·저장 용량 변화가 생겨도 잘못된 계획을 그대로 저장하지 않는다.
- 제출한 요일 배열을 복사하고 프로필을 고정한다. 처리 전에 프로필이 바뀌면 등록을 중단하며 새 프로필로 옮겨 저장하지 않는다.
- 모든 새 일정을 한 번의 상태 변경으로 저장한다. 파일은 원자적으로 교체하며, 저장 실패 상태를 사용자에게 표시한다.
- 분류 기본 알림을 상속한다. 새 설치의 모든 알림 기본값은 꺼짐이다. 기존에 직접 켠 분류는 그 선택을 유지한다.

## ID와 삭제 범위

| 값 | 의미 |
| --- | --- |
| 일정 Id | 매 회차의 고유 PK. 편집해도 유지 |
| CategoryId | 공격대/공대별 표시 분류. 삭제 묶음의 기준이 아님 |
| SeriesId | 이번 일괄 등록 한 번에 부여하는 새 GUID. 다른 등록과 공유하지 않음 |
| SeriesIndex | 이번 등록 안의 최초 시간순 위치. 개별 일정을 다른 날로 옮겨도 유지 |

예전에 수동 등록한 일정이나 단순히 같은 분류인 일정은 일괄 삭제에 포함하지 않는다. 중복을 제외한 새 일정만 이번 SeriesId에 속한다. 같은 패턴을 나중에 확장 등록하면 새로 추가된 회차는 다른 등록 묶음이다.

날짜 카드의 **삭제**를 누르면 확인 창에서 이번 일정만 / 이번 및 이후 일정 / 이 등록의 모든 일정을 선택한다. 각 범위의 개수를 보여준다. ‘이후’는 이동한 날짜가 아닌 **등록 당시 순서**다. 창에도 이를 설명한다. 동일 프로필·SeriesId만 대상으로 하며 다른 공대·프로필·등록 묶음은 보존한다. 한 개만 남으면 단건 삭제 확인만 제공한다.

삭제한 일정의 개별 알림과 숨김 참조도 정리한다. 이미 기록된 알림 내역은 이력으로 남지만 대기 채팅은 존재·설정을 재확인하여 삭제한 일정의 늦은 채팅을 보내지 않는다.

## 편집과 제한

직접 등록한 일정 카드의 본문 클릭은 동작하지 않는다. 상단 수정 버튼으로 별도 편집 창을 열고 같은 창에서 알림을 정한다. 일괄 등록 후 개별 회차의 제목·분류·시각 변경은 가능하다. 전체 반복 패턴 일괄 수정·무기한 생성·온라인 공유·공대원/출석 관리는 제공하지 않는다.

편집 중 다른 동작으로 일정이 삭제되면 저장을 거절한다. 삭제된 회차를 편집 저장으로 되살리지 않는다. 알림과 일정 편집은 한 상태 변경으로 처리한다. 메인 창을 닫아도 독립 편집 창의 초안은 유지한다.
