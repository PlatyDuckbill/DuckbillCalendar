# 0.3.2 배포 후보 · 5회 검토

이 문서는 배포 전 검토 기록이다. 이후 사용자 요청에 따라 실제 공개했으며 최신 상태는 [0.3.2.0 배포 기록](RELEASE-0.3.2.0.md)을 따른다.

2026-11-14 KST. 대상: 누적된 디자인·개인 분류·알림·공격대 반복 등록 요청과 이벤트 링크 오류·매년 오구데이. 작업은 로컬 빌드와 배포 후보 생성까지 진행한다. 원격 GitHub Actions 변경·수집기·Release·설치 저장소 게시와 게임 자동 재로드는 수행하지 않는다.

## 반영 범위

- 날짜 카드의 추가 하단 버튼 영역을 제거하고 상단에 직접 등록 일정의 수정·숨기기·삭제, 공개 일정의 알림 설정·숨기기·추가 메뉴를 배치했다. 직접 등록 일정 본문은 클릭해도 편집하지 않는다.
- 알림 세부 설정과 일정 편집은 배경을 밝게 덮지 않는 독립 창이다. 직접 등록 일정은 수정 창에서 알림도 변경한다. 내역은 종 버튼으로 메인 화면 안에서 확인한다.
- 기본 개인·공격대 분류도 삭제할 수 있다. 모든 분류에 아이콘/색상 미리보기를 표시하며 사용자 분류는 행 끝의 삭제 버튼을 사용한다. 삭제 확인에서 이동할 분류 또는 실제 미분류를 선택한다.
- 공격대 반복 등록은 요일별 다른 시각·등록할 주 수·주 간격·달력 날짜 선택·미리보기·중복 제외를 제공한다. 등록한 회차별 편집과 이번/이후/등록 전체 삭제를 지원한다.
- 새 설치의 전체 알림·새 공지·새 이벤트·분류/일정·채팅은 모두 꺼짐이다. 기존에 저장한 선택은 유지한다. 목록 체크박스로 직접 켜고 끄며 전체 꺼짐을 명시한다.
- 시각 있는 달력 표식에 HH:mm, 마감/만료에 경고 배지, 공격대 아이콘, 가운데 맞춘 오늘 숫자/미확인 수를 적용했다.
- 이벤트 목록을 상세 안내로 열던 링크를 수정했다. 매년5월9일에는 실제 오리부리 꼬마친구 아이콘과 오구데이를 작게 표시한다.

## 루프1 · 반복 등록과 삭제 도메인

검토: 요일마다 다른 시각, 시작일이 선택 요일 중간인 경우,2주 이상 간격, 연말·윤년, 최소/최대 기간, 잘못된 시각, 과거 일정, 중복,2000개 한도, 다른 프로필/분류/등록 묶음.

결과: 한국 시간으로 유한한 날짜를 전개하고 저장 직전에 최신 상태로 다시 계획한다. 미리보기와 확정 사이 상태 변화를 검증한다. 날짜를 추측하거나 무기한 백그라운드 생성하지 않는다.

삭제 범위를 분류나 제목으로 추측하면 다른 공대 일정이 지워질 수 있어 **회차 Id / 분류 CategoryId / 등록 SeriesId / 원래 순서 SeriesIndex**를 분리했다. 이후 삭제는 개별 시각을 이동해도 최초 순서로 판단한다. 한 번에 등록한 묶음과 활성 프로필 밖으로 범위를 확대하지 않는다. [상세 정책과 예시](WEEKLY-RAID-SCHEDULES.md).

## 루프2 · 저장·경합·알림

검토: 프로필 전환 직전 등록, 편집 중 삭제, 초안 저장과 알림 변경의 분리, 분류 삭제 후 일정/개별 알림 유지, 파일 저장 실패·재시작, 알림 중복·시각 변경·전투 대기.

발견/수정:
- 편집 중 삭제된 회차가 저장 시 되살아날 수 있던 경로를 차단했다. 기존 일정임을 기대하는 저장은 존재와 프로필을 다시 확인하며 실패 이유를 편집 창에 표시한다.
- 일정과 알림 변경을 한 상태 갱신으로 합쳤다. 등록 제출 시 요일 배열과 프로필을 복사하고 프로필이 바뀌면 중단한다.
- 기존 설정을 최초 변경하기 전 유효한 원문 JSON 스냅샷 **state.before-v032.json**을 한 번 저장한다. 기존 스냅샷을 덮어쓰지 않는다. 구형 알림 형식 백업 state.pre-notifications-v1.json도 유지한다.
- 삭제 시 대상 일정의 개별 알림·숨김 참조를 함께 제거한다. 과거 알림 내역은 이력으로 유지하고 대기 채팅은 존재·설정·시각을 다시 검사한다.
- 기본 꺼짐 변경은 새 기본값에 적용한다. 기존 사용자가 직접 켠 알림을 무단 초기화하지 않는다.

저장 실패 중 채팅을 보내지 않는다. 소비 기록 저장 직후 실제 출력 전에 프로세스가 종료되면 채팅은 누락될 수 있지만 내역은 남는다. 중복 전송보다 이 중단 경계의 누락을 허용하는 기존 계약을 문서화했다. 게임 종료 중 알림/OS 예약 실행은 제공하지 않는다.

## 루프3 · UI와 작은 창

검토: 차콜/미드나이트/라이트,620×480·1060×720·1320×1050,1/1.5/2배율, 본문/버튼 충돌, 스크롤, 독립 창 초안, 아이콘/색상/알림 열 폭, 오늘/미확인 숫자.

발견/수정:
- 카드 하단 액션이 높이를 키우던 문제를 상단 컴팩트 액션으로 해결했다. 제목은 버튼 영역과 겹치지 않게 자른다.
- 좁은 반복 등록 창은 기본/요일·시각/미리보기 탭으로 나누고 하단 등록/닫기 버튼을 유지한다. 큰 배율에서는 중복 제목/표 머리글을 줄였다.
- 분류 표는 좁은 폭에서 열 너비를 줄이고2열 전환 기준을 높여 색상·알림·삭제가 밖으로 나가지 않게 했다.
- 독립 편집 창은 메인 창을 닫아도 그린다. 실제 분류 이름으로 편집 제목을 표시한다.
- 오늘/미확인 배지는 실제 글자 크기로 가운데를 맞추고 이웃 버튼을 침범하지 않도록 크기와 모서리를 조정했다.

최종 회귀 도중1.5배율 아이콘 클릭 검사가 간헐적으로 실패했다. 검사에서 비동기 저장 완료 전의 화면 좌표와 콤보의 첫 자동 배치 좌표를 사용하던 부분을 정리했다. 저장 큐를 비우고 콤보 배치가 안정된 뒤 실제 목표를 읽도록 했으며 이후 연속 native 실행을 확인했다. 실패를 재실행 통과만으로 무시하지 않았다.

실제 MainWindow의 DrawData를 CPU 렌더링해 세 테마와 작은2배율 창을 시각 확인했다. 이는 실제 게임 GPU/글꼴/DPI 인수 검사를 대신하지 않는다.

## 루프4 · 링크와 오구데이

원인: 일부 정상 피드의 Evidence.Url은 날짜를 입증한 이벤트 **목록**이며 실제 개별 href는 근거 Note의 ‘개별 안내:’에 있었다. 단순히 첫 Evidence.Url을 열면 목록으로 갔다.

수정: 공통 OfficialEventLinks가 참조 근거와 선택 단계를 기준으로 실제 상세 링크를 고른다. 기존 목록 근거를 상세 수집 근거로 위조하거나 피드 스키마를 바꾸지 않는다. HTTPS·공식 호스트·443포트·인증정보 없음, 숫자 이벤트 ID 일치를 검사한다. 일반 뉴스/이벤트 목록·잘못된 상세 ID·외부 도메인은 반환하지 않으며 안전한 상세 링크가 없으면 열기 동작을 제공하지 않는다. 상세 URL을 번호로 추측해 생성하지 않는다.

실제 공식771/772상세 URL은 HTTP200과 각 캠페인 리디렉션을 확인했다. 제목과 최종 캠페인이 일치했다. 검사는 날짜/단계 우선순위·HTML 쿼리·후행 문장부호·외부/인증정보/다른 ID를 다룬다.

오구데이는 원격 피드나 개인 일정으로 저장하지 않고 월/일로 판정한다. 매년5월9일, 달력 작은 아이콘+이름과 날짜 팝업에만 표시한다. 이벤트 건수·알림·정렬·숨김에 가짜 일정을 추가하지 않는다. 작은 칸에서는 아이콘 위주로 줄인다. 기존 전장 오늘/내일은 유지한다.

[공식 오리부리 꼬마친구 아이콘](https://na.finalfantasyxiv.com/lodestone/playguide/db/item/87347462fe9/)의40×40 PNG를 주 DLL에 포함한다. 런타임 다운로드 없이 Dalamud 공유 텍스처를 프레임 안에서 사용하고 준비 전에는 로컬 도형으로 대체한다. PNG·native 렌더 fixture·실제 배포 DLL 내 리소스 SHA256을 확인한다. 저작권/출처는 THIRD-PARTY-NOTICES.md에 기록했다.

## 루프5 · 회귀·패키지·운영 경계

최종 자동 검사: Core291 + Infrastructure203 + Model151 + Native561 + 수집 도구117 + CLI30 = **1353개**. 한국어 리소스222개, 게시→실제 소비자 수신→손상 시 이전 정상본 유지→재시작 통합 smoke와 실제 DLL의 버전/아이콘 SHA256/번들 피드2개 검사는 별도다.

Release는 KR Dalamud API15.0.3.9 참조로 컴파일한다. prepare-dev.ps1은 필요한 Plugin/Core/Infrastructure DLL·manifest·deps·안내·내부 SHA 목록을 모으고 ZIP 내부 파일을 다시 열어 원본 SHA와 비교한다. 검토한 묶음을 덮어쓰지 않는 타임스탬프 이름을 사용한다.

수집/게시 아키텍처는 [앞선5회 파이프라인 점검](PIPELINE-AUDIT-2026-11-13.md)을 따른다. 공개 피드 수신과 전장 수신, 로컬 편집, 알림 계획, UI를 나누며 공유 상태 반영을 직렬화한다. 알림/오구데이가 추가 HTTP 요청을 만들지 않는다. 개인/계정/공대 정보를 수집 서버로 보내지 않는다. 수동 갱신도 기존 온라인 설정·5분 제한·Retry-After를 지킨다.

이번 로컬 소스와 workflow 변경은 아직 원격에 게시하지 않았다. 로컬 수정 완료와 운영 원격 반영을 구분한다. 번들96건을 새 수집 결과로 자동 교체하지 않았다.

추가 발견/수정: 독립 알림 창의 취소가 창을 닫지 않던 연결을 수정했다. 창을 연 채 분류가 삭제되면 저장을 막고 분류 편집에서 존재하지 않는 항목을 조회하지 않는다. 프로필이 바뀐 초안은 저장할 수 없으며, 큐에 들어간 알림 변경도 제출 시 프로필을 고정해 다른 프로필로 섞이지 않게 했다. 실제 취소/삭제 중 창 native 검사6개와 프로필 경합/삭제된 분류 Model 검사3개를 추가했다.

## 배포 전 인수와 되돌리기

1. 게임에서 플러그인을 끄고 기존 플러그인 폴더와 로컬 설정 폴더를 따로 보관한다.
2. 배포 후보 폴더의 DLL3개·manifest·deps를 함께 사용한다. 자동 재로드는 하지 않는다.
3. 인게임에서 세 테마, 실제 글꼴/DPI, 좁은 창, 오늘/월 이동, 카드 버튼, 반복8건 등록과3개 삭제 범위/취소, 프로필 전환, 분 단위 충전/초기화를 확인한다.
4. 알림을 명시적으로 켠 테스트 일정으로 시각·채팅·전투 대기를 확인한다. 전투 중 자동 요청만 보류되는지, 수동 갱신/기존 제한이 유지되는지 확인한다. 실사용 알림을 임의 초기화하지 않는다.
5. 공식 링크2개와5월9일을 확인하고 로그 오류가 없는지 본다. 이 게임 통합 인수는 현재 환경에서 자동 수행하지 않았다.
6. 문제가 있으면 게임에서 플러그인을 끄고 기존 바이너리 폴더를 복원한다. 현재 state.json을 별도 보관한 후 필요 시 state.before-v032.json을 복사해 복원한다. 이 스냅샷 이후 편집은 복원 시 되돌아간다. snapshot이 없는 새 설치는 별도 백업을 사용한다.
7. 수집기/workflow 원격 반영과 플러그인 배포는 이 인수 뒤 별도 게시 단계에서 수행한다.

현재 자동 검사 통과를 인게임 검증 완료로 표현하지 않는다. 배포 후보·소스 스냅샷 경로와 SHA256은 생성된 artifacts/release-candidate의 매니페스트에 기록한다.

## 후속 요청 · 오구데이 배경 제거

원본 아이템 타일의 배경을 제거한 투명 편집본 bitty-duckbill-cutout.png를40×40으로 적용했다. built-in image_gen에 “파란/회색 아이템 타일·테두리·배경 빛만 제거, 오리부리 포즈·방향·색·실루엣 유지, 투명 배경”으로 요청했다. 원본은 보존한다. 실행 중 이미지를 생성하거나 내려받지 않는다. 내장 PNG·RGBA fixture·실제 DLL SHA 검사를 편집본에 맞췄다.

## 후속 요청 · 대표 아이콘

DuckbillTweak·DuckbillFisher와 같은 계열의 청록 원형 배지·크림 제목·갈색 오리너구리로 대표 아이콘을 제작했다. 최종 선택은 큰 달력을 바라보며 앞발을 편하게 내린 자세(v7-natural)다. 512×512 투명 PNG, README, 버전 태그 IconUrl, 로컬 설치 목록 images/icon.png와 배포 후보 ZIP에 연결한다. 선택한 원본·프롬프트와128/64px 확인본은 [assets](../../assets/README.md)에 보존한다. 이전 시안76개는 ZIP 내부 SHA256을 전부 확인한 뒤 artifacts/design-archive로 보관하고 현재 assets는6개 파일로 정리했다. Fisher/Tweak 선택본은 artifacts/icon-handoff에 별도 정리했으며 해당 두 프로젝트는 아직 변경하지 않았다. 원격 게시하지 않았다.

## 후속 요청 · 최초 배포 업데이트 내역

설정의 업데이트 내역 버튼과 /dbcal changelog (/duckbillcalendar changelog)로 같은 본문 페이지를 연다. 현재0.3.2.0의 최초 배포 한 건만 포함하며 개발 중 변경 이력은 공개 내역에 나열하지 않는다. 게시일을 미리 만들지 않는다. 읽을 때 HTTP/로컬 설정 쓰기를 하지 않고, 작은 창에서는 본문이 스크롤하며 설정 복귀 버튼은 위에 남는다. 처음 실행할 때 강제로 열지 않는다. 설치 manifest의 Changelog와 루트 CHANGELOG.md에도 최초 배포 안내를 제공한다.

새 버전을 추가할 때 UI/ReleaseNotesPanel.cs의 CurrentVersion과 Entries, csproj Version/Changelog, CHANGELOG.md를 함께 갱신한다. 배포 후보 생성 단계에서 실제 DLL/manifest/내역의 버전 불일치를 막는다. Native UI10검사를 추가해 전체 자동 검사1363개가 되었다.
