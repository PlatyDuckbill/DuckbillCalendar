# 전투·임무 보류와 숨김 범위 사용성 점검

> 후속0.2.5에서는 자동 창 숨김을 제거하고 자동 요청 보류만 유지한다. 현재 동작은 [설정·충전 보정](SETTINGS-AND-RENEWAL-REVIEW.md)을 참고한다.

2026-11-13 · 0.2.4.0. 기존 수집/게시 구조를 유지하고 실제 사용 경계와 숨김 단위를 한 차례 점검·수정했다.

## 수정한 문제

기존 숨김은 `HiddenEventIds`의 행사 전체 숨김뿐이었다. CCRC의 선발전·참가신청·예선·결선은 한 행사에 들어 있으므로 선발전에서 숨겨도 네 단계가 모두 사라졌다. 이제 기본 ‘이 일정만 숨기기’는 `(eventId, phaseId)`를 저장한다. 시작·마감·진행 중 표시는 함께 숨기고 다른 단계는 유지한다.

‘관련 일정 모두 숨기기’는 행사 ID 전체를 숨긴다. CCRC는 같은 대회의 네 단계만 포함한다. 다른 ID의 관계는 기존에 검토한 구매 캠페인 또는 버전·날짜·공유 근거·유일한 후보를 만족한 점검/패치 연결만 허용한다. 같은 제목/분류/근거 또는 같은 날이라는 이유만으로 관계를 확장하지 않는다. 메뉴에 개수를 표시하고 툴팁에서 행사·단계 목록을 볼 수 있다. 묶음 카드에서는 그 안의 개별 항목도 따로 숨길 수 있다.

기존 자동 수집은 단계 ID에 배열 순서를 사용했다. 순서 변경이나 항목 추가로 개인 숨김/알림 키가 달라질 수 있어, 이전 단계와 대조한 안정 ID로 변경했다. 정규화한 라벨이 같은 단계는 기존 ID를 유지하며, 새 단계는 역할·정규화한 라벨의 해시로 식별한다. 라벨이 달라진 단계를 같은 역할·날짜라는 이유만으로 승계하지 않는다. 삭제 후 교체된 다른 일정에 숨김이 옮겨 갈 수 있기 때문이다. 원문 단계가 구분되지 않으면 추정 연결하지 않고 자동 준비를 실패시킨다. 수동 검토 결과를 기존 이벤트와 병합할 때도 같은 원칙으로 기존 단계 ID를 보존한다. 공개 JSON 형식에 새 관계 필드를 추가하지 않았다.

## 확인한 사용 시나리오

| 경우 | 결과 |
| --- | --- |
| CCRC 선발전만 숨김 | 참가신청·예선/본선·결선 유지. 선발전의 시작/마감/진행 중 표시만 제거 |
| CCRC 관련 전체 숨김 | 같은 CCRC 행사만 숨김. 다른 대회/패치/분류 체크는 유지 |
| 같은 제목·분류를 가진 다른 대회 | 다른 행사 ID이므로 연결하지 않음 |
| CE 구매/혜택 전체 숨김 | 검토된 구매 캠페인만 대상. 얼리 액세스·정식 출시 제외 |
| 같은 패치 버전의 점검 후보가 여러 개 | 관계를 추정하지 않음 |
| 제목·기한·단계 순서 변경/단계 추가 | 기존 단계 키 유지. 숨김 대상이 다른 일정으로 이동하지 않음 |
| 재시작·개별 복원·전체 복원 | 개별/행사 전체를 구분해 유지·복원 |
| 기존 버전의 행사 숨김 | ‘행사 전체’로 유지. 원래 클릭한 단계를 알 수 없어 자동 변환하지 않음 |
| 원문/새소식/알림 | 숨김은 달력 투영만 변경. 원본과 기존 알림 선택은 유지 |

## 전투·임무 중 동작

기본으로 전투·임무/PvP 중에는 공개 일정/전장 자동 요청을 보류한다. 지역 이동·영상·미접속/플레이어 미준비 상태도 자동 요청을 기다린다. 안전한 상태가15초 유지되면 기존 갱신 시각·쿨다운·서버 재시도 제한에 따라 재개한다. 보류 기간의 횟수를 누적하지 않으므로 종료 후 요청 폭주가 없다.

진행 중인 자동 요청은 취소하며 사용자 취소를 통신 실패로 계산하지 않는다. 직접 시작한 요청은 전투 보류로 취소하지 않는다. 이미 완료·검증해 저장한 결과를 취소 때문에 되돌리지는 않는다. 개인 일정 저장과 알림 발송 기록 저장도 중단하지 않는다.

전투 중 창 숨김과 임무/PvP 중 창 숨김은 각각 설정할 수 있다. 창을 닫아 버리지 않고 그리기를 보류하므로 상태를 유지한다. 작성 중이던 개인 일정 편집창도 다시 열며 초안을 보존한다. `/dbcal`, 설정 열기 등 명시적인 열기는 현재 상황에서 창을 표시할 수 있다. 새 전투/임무나 지역 변경에는 이전 수동 표시 예외를 초기화한다. 로딩·영상 중에는 수동 표시도 기다린다. 창을 수동으로 열어도 자동 요청 보류는 해제하지 않는다.

전장은 별도의 ‘전장 지금 갱신’을 제공한다. 수동 요청도 기존 서버 재시도 제한과5분 연속 요청 제한을 지킨다. 전장 불러오기를 끄면 대기 중인 수동 요청도 취소한다. 기존 채팅 알림의 전투/임무 억제 규칙은 유지한다.

## 남는 경계

- 공식 ID가 없는 별도 점검 중에는 날짜를 포함한 내부 행사 ID를 사용하는 경우가 있다. 그 ID가 바뀌면 새 일정으로 취급하며 옛 숨김을 추정해 적용하지 않는다. 동일 버전이라고 다른 점검까지 숨기는 것을 피하기 위한 범위다.
- 같은 행사에 새 단계가 추가되면 행사 전체 숨김은 계속 적용된다. 새로운 별도 행사 ID까지 이름·분류로 추정해서 확대하지 않는다.
- 공식 단계 라벨이 바뀌면 새 단계 ID가 생길 수 있다. 기존 개별 숨김은 새 단계에 자동 적용하지 않으며, 필요하면 새 단계를 다시 숨긴다. 공백만 바뀌거나 날짜·행사 제목·단계 순서만 바뀐 경우에는 기존 ID를 유지한다.
- CCRC 원본 category와 화면의 대회 분류는 기존 표현을 유지했다. 숨김 키와 관계 판정은 이 분류값에 의존하지 않는다.
- 게임 조건 플래그를 연결한 코드와 상태 전이/가짜 HTTP/native ImGui 클릭은 검증하지만 실제 게임의 모든 콘텐츠·컷신·PvP·입력/종료 동작을 재현한 결과는 아니다. 임무 판정은 BoundByDuty 계열 조건이며 인스턴스 방 번호별 허용 목록은 추가하지 않았다.
- 수정은 로컬0.2.4이며 GitHub source/data/Release 게시와 게임 자동 로드는 수행하지 않았다. 수집기의 단계 ID 보강도 원격 적용 전이다.
