# 일정 파일과 전체 백업

2026-11-16 개발본. 설정의 **일정 파일과 백업**에서 **일정 내보내기 (.ics) / 일정 가져오기 (.ics)**와 **전체 백업 (.json) / 전체 백업 복원 (.json)**을 각각 한 쌍으로 제공한다. 각 버튼은 해당 확장자의 파일 선택기만 열고, 직접 다른 형식을 지정하면 맞는 버튼을 안내한다. 공개0.5.0.0 이후 미배포 변경이며 외부 캘린더·게임 실기는 확인 대기다.

## 일정 교환 (.ics)

- 내보내기는 현재 프로필의 개인 일정과 이용권 만료일 전체를 포함한다. 공개 피드·다른 프로필·화면 필터는 내보내기 대상이 아니다. 이용권은 외부 앱에서 만료 시점의 일반 일정으로 보인다.
- RFC5545의 VCALENDAR/VEVENT, VERSION/PRODID, 안정된 UID, UTC DTSTAMP/DTSTART/DTEND, VALUE=DATE와 TEXT 이스케이프를 사용한다. CRLF와 UTF-8 75옥텟 줄 접기를 적용하며 한글 코드 포인트를 나누지 않는다.
- 시각은 UTC로 내보내고 종일은 시각 없이 날짜로 내보낸다. DTEND는 배타적 끝이다. 게임 달력은 한국 시간으로 표시하며 PC 시간대에 의존하지 않는다.
- 가져오기는 UID·SUMMARY·DTSTART가 있는 단건/기간 일정만 지원한다. 종료·설명·위치를 보존하며 위치는 메모에 합친다. 종일, UTC, 운영체제가 해석하는 TZID를 지원한다. 운영체제에 없는 사용자 정의 시간대와 DST 중복/존재하지 않는 시각, 시간대 없는 floating time은 제외한다. 별도 VTIMEZONE 규칙을 실행/재현하지 않는다.
- 반복 규칙 RRULE/RDATE/EXDATE·RECURRENCE-ID, DURATION, 취소와 길이/범위 초과는 미지원 건수로 표시한다. 초대 대상·회의·외부 알림은 가져오지 않는다. 무한 반복을 임의 회차로 바꾸지 않는다. 기존 공격대 유한 일괄 등록은 각 회차를 독립 VEVENT로 내보낸다.
- 미리보기에 추가·중복·미지원 건수와 최대5개 제목/시점을 표시한다. 확인하면 현재 프로필의 개인 일정으로 추가하고 알림은 명시적으로 꺼짐을 저장한다. 기존 일정과 알림은 보존한다.
- 같은 프로필의 동일 UID는 중복으로 제외한다. UID가 다른 유사 일정은 합치지 않는다. 같은 UID의 수정본을 자동으로 덮어쓰지 않으며 삭제한 일정을 다시 가져오면 재등록할 수 있다.
- 종료 시각이 있는 일정은 날짜 상세에도 기간으로 표시한다. 시작 시각을 수정하면 기간 길이를 유지해 종료를 옮긴다. 날짜/시각 형식 전환은 거절한다.
- 파일은 최대2MiB, 입력 VEVENT/전체 저장 일정 최대2,000개, 제목80자·메모1,000자·UID512자·입력 날짜2020~2100년이다. 잘못된 컨테이너는 전체 거절하고 지원하지 않는 개별 일정만 제외한다.
- 파일 교환이며 계정 연결·구독·양방향 실시간 동기화가 아니다. 외부 앱의 반복/알림/서식 전체를 지원한다고 보장하지 않는다.

## 전체 백업 (.json)

- Format DuckbillCalendar.Backup / FormatVersion1 / CreatedAt / State 계약이다. 모든 로컬 프로필·일정·이용권·사용자 분류·알림 선택·읽음/소비 이력·화면 설정을 보존한다. 공개 피드/캐시·전장 캐시·편집 중 초안은 포함하지 않는다.
- 확장자·형식·버전·기존 LocalState 검증을 통과한 파일만 미리보기에 올린다. 불완전한 JSON·잘못된 중첩 값·저장 가능한 크기 초과는 적용하지 않는다.
- JSON 복원은 전체 로컬 상태 교체이며 미저장 편집을 닫는다. 받은 알림 내역은 복원하지만 과거 채팅 대기 상태와 메모리 예약은 재전송하지 않는다. 백업 시점 이후의 소비 기록은 백업에 없으므로 현재 알림 조건을 다시 평가할 수 있다.
- .ics 가져오기와 JSON 복원 모두 적용 전 현재 상태를 설정 폴더의 state.before-transfer-시각-GUID.json에 같은 백업 계약으로 보존한다. 보존에 실패하면 적용하지 않는다. 화면에 절대 경로를 표시하며 이 파일도 파일 가져오기로 복원할 수 있다.
- 미리보기부터 적용까지 상태 변경 버전을 검사하며 낡은 미리보기는 다시 선택해야 한다. 파일 I/O는 기존 직렬 작업자 큐에서 실행하고 적용은 Pump에서 진행한다. 종료 뒤 늦은 완료를 적용하지 않는다.
- 적용 후 기존 원자적 저장을 따른다. 저장에 실패하면 이전 디스크 성공본과 별도 보존본을 유지하고 미저장/실패를 표시한다. 이 상태에서 재로드하면 메모리의 변경을 잃으므로 먼저 실패 원인을 해결해야 한다.
- 내보내기는 새 파일만 작성한다. 기존 파일은 덮어쓰지 않으며 임시 파일 완성 후 이동한다. 필요한 경우 다른 이름을 고른다.
- 종료/UID는 PersonalEntry의 선택 필드 End/CalendarUid다. 값이 없으면 JSON에서 생략해 기존 자료 형식을 유지한다. 값이 있는 새 자료는 이전 플러그인이 읽지 못할 수 있으므로 이전 버전 복귀에는 적용 전 보존본을 사용한다.

## 근거와 도입 내역

- [RFC5545](https://www.rfc-editor.org/rfc/rfc5545.html), 고정 문서 RFC5545/2009-09의3.1·3.3.5·3.3.11·3.6.1·3.8.2·3.8.4를 참조했다. 표준 형식을 자체 구현했고 외부 소스 코드를 복사하거나 라이브러리/데이터를 도입하지 않았다.
- [Google Calendar 가져오기 안내](https://support.google.com/calendar/answer/37118?hl=en), 확인2026-11-16. .ics 지원과 파일 교환 동선만 참고했다. Google API/OAuth·온라인 접속을 제품에 추가하지 않았다.

## 대표 확인 순서

1. 개발 DLL에서 한글/쉼표/세미콜론/여러 줄 메모, 종일·시각·기간 일정을 .ics로 내보낸다. 구글 캘린더의 설정→가져오기/내보내기에서 새 캘린더에 가져와 제목·한국 시각·종일/기간을 대조한다.
2. .ics 가져오기 미리보기의 제목·건수를 보고 추가한다. 같은 파일 재선택 시 중복 건수가 늘고 추가가0인지 확인한다. 반복 규칙은 제외 건수에 들어가며 알림이 임의로 켜지지 않아야 한다.
3. JSON 백업 후 자료를 변경하고 복원한다. 교체 안내/미리보기·보존 경로·복원된 일정/이용권/분류/알림을 확인하고 재로드해 저장 여부를 확인한다.
4. 취소·잘못된 파일·기존 이름으로 내보내기·미리보기 중 편집은 기존 자료를 유지하거나 재선택을 안내해야 한다. 복원 뒤 오래된 편집과 대기 채팅이 실행되지 않아야 한다.
