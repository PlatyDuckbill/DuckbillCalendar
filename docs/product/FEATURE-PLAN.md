# 화면·기능 개선 및 출시 범위

> 2026-11-12 구현 갱신: 아래는 11/11 설계 검토다. 실제 첫 개발판의 완료·대기는 [현재 상태](../STATUS.md)와 [10회 개발 기록](../development/DEVELOPMENT-LOOPS.md)을 따른다.

분석 기준: 2026-11-11, 목업 0.2의 코드와 기존 기획 문서. 이 문서는 제품 설계 및 코드 관찰 결과다. 브라우저 렌더링이나 인게임 실기 결과를 뜻하지 않는다. 목업 후속 개선의 적용 여부는 [검증 기록](../VERIFICATION.md)을 따른다.

## 1. 유지할 사용자 결정

- Dalamud에 맞는 **상단 가로 탭**을 유지한다. 좌측 사이드바를 다시 도입하지 않는다.
- 독립 전장·PvP 탭을 두지 않는다. 달력 아래에 오늘·내일 전장 이름을 가볍게 보여준다.
- 크컨 시즌과 PvP 시리즈의 시작일을 각각 달력 날짜 항목으로 표시한다. 종료 미정이어도 알려진 시작일은 보존한다.
- 이벤트를 **기간 막대 / 시작·종료만** 중 선택하고, 선택을 로컬 저장한다.
- 작은 여백과 한 줄 요약을 유지한다. 큰 대시보드 카드나 기능별 새 탭을 늘리지 않는다.

제품의 핵심은 오늘 놓칠 수 있는 마감과 다음 일정을 빠르게 확인하는 것이다. 공개 일정의 사실과 개인의 참여·수령 상태는 독립된 정보다.

## 2. 1차 루프 — 현재 목업에서 발견한 문제

아래는 해당 함수·데이터 구조를 읽어 확인한 초기 관찰이다. 후속 수정 후에도 회귀 검증 시나리오로 유지한다.

| 발견 | 영향 | 우선순위·수정 방향 |
| --- | --- | --- |
| `dataPage()`와 운영자 검수 탭이 일반 사용자 화면에 노출됨 | 사용자가 자신이 검수해야 최신 일정을 받는다고 오해할 수 있음 | P0: 기본 탭은 달력·새소식·이용권·설정. 운영 도구는 별도 도구/개발자 표시로 한정 |

| `milestonesHTML()`의 시즌/시리즈 제목이 고정됨 | 신규 시즌 데이터가 들어와도 예전 번호로 표시될 수 있음 | P0: 제목·시작일은 선택된 피드 event/phase에서 읽음 |
| `renderCompact()`의 오늘 마감 시각이 `23:59` 고정임 | 17:00 마감 등 실제 종료와 다른 시각 표시 가능 | P0: 실제 선택한 단계의 시각/정밀도로 표시 |
| 긴 기간 막대의 행 수에 상한이 없음 | 이벤트가 늘면 월간 달력이 길어져 컴팩트 요구를 잃음 | P0: 기본 3행 이내 + 날짜별 더보기 |
| 수령 기간이 참여 기간과 같은 강도로 길게 표시됨 | 한 이벤트가 여러 줄을 차지하고 참여·수령을 혼동 | P0: 단계 문구·구분선. 수령 막대 별도 표시 옵션 |
| 확인 시각이 스냅샷 문구로 고정됨 | 수집 실패·검수 지연·단순 다운로드 성공을 구분할 수 없음 | P0: 원문 수집/내용 검수/클라이언트 확인 시각을 분리 |
| 압축 CSS에 8~10px 글자와 17px 막대가 사용됨 | 좁은 폭에서는 잘린 제목·단계가 읽기 어려울 수 있음 | P0: 글자를 줄이는 것보다 생략·상세 노출·배율을 활용. 실제 DPI 검증 전 가독성 통과로 보고하지 않음 |

## 3. 2차 루프 — 개선안의 부작용과 조정

### 사용자 화면과 운영 도구

일반 사용자의 설정에는 데이터 출처, 원격 갱신 선택, 마지막 성공/검수 시각, 갱신 실패 원인, 수동 새로고침·파일 가져오기를 둔다. 공개 피드를 검수·게시하는 권한이나 동선은 포함하지 않는다.

목업의 운영자 표시 토글은 검토용 기능이다. 켜더라도 GitHub 게시 권한·계정 연결이 생기지 않는다. 토글을 껐을 때 운영 화면을 보고 있다면 설정으로 이동하고, 숨겨진 탭은 키보드 방향키 이동 대상에서도 빠져야 한다. 실제 제품의 수집·검수 UI는 게임 프로세스 밖에 두는 편이 역할과 자격 증명 관리에 맞는다.

### 수령 막대의 기본 표시

수령 기간은 길고 참여 기간과 겹치는 경우가 많다. 기본적으로 수령 막대만 숨기는 옵션은 화면 밀도를 줄일 수 있다. 단, 이것은 **그리기 옵션**이다. 보상 수령 마감 marker, 오늘 마감 집계, 설정된 알림, 선택한 날짜에 진행 중인 단계 목록을 제거하면 안 된다.

`기간 막대`와 `시작·종료만`은 날짜를 보는 방식이고, 참여·수령은 데이터 단계다. 둘을 같은 설정으로 취급하지 않는다. 수령 막대 설정은 설정 화면에 두어 달력 도구줄에 토글을 과도하게 늘리지 않는다.

### 막대 3행 상한

상한 밖의 일정은 삭제하거나 한 주 전체에서 같은 개수로 표시하지 않는다. 해당 날짜에 실제로 걸치는 숨겨진 phase 수를 구해 `+N`으로 보여준다. `+N`을 누르면 그 날짜의 모든 일정·단계가 나온다. 월간 달력만 보았을 때 숨겨진 일정이 있다는 사실을 알 수 있어야 한다.

한 주의 3개 행은 렌더링 상한이다. 계산된 전체 기간·알림·검색 결과는 그대로 유지한다. 가능한 경우 동일 phase의 행을 연속 주에서 유지해 눈으로 따라가기 쉽게 하되, 빈 행 재사용과 상한 준수를 우선한다. 여러 날 막대는 제목과 phase 문구를 함께 제공하고, 잘리면 호버/선택 상세에서 모두 읽을 수 있어야 한다.

### 알림과 관심 필터

첫 버전에서는 즐겨찾기와 알림을 별도 기능으로 동시에 늘리지 않아도 된다. `알림 설정 일정만` 필터는 그 이벤트에 하나 이상의 선택된 phase 알림이 있는지로 판정한다. 일반 `관심`이라는 이름을 사용한다면 알림과의 관계를 도움말에 명시한다.

알림을 켜는 UI에서는 `참여 종료`, `보상 수령 종료`, 필요 시 `시즌/시리즈 시작`을 각각 선택한다. 미정 날짜는 선택을 저장할 수 있지만 상태는 `일시 확정 대기`이며 임의 알림 시각을 만들지 않는다. 날짜만 알려진 경우 분·시간 단위 알림을 만들지 않는다.

기존 eventId 선택을 옮길 때 새로운 시작 알림까지 조용히 추가하지 않는다. 기존 목업은 실제 발송을 하지 않았으므로, 종료 단계 선택으로 옮긴 상태와 변경 안내를 보여줄 수 있다. 실제 플러그인 마이그레이션에서는 버전별 의미를 고정해야 한다.

### 단계 선택과 필터의 일관성

기간 막대·종료 marker·일별 목록 어디에서 눌러도 선택은 eventId + phaseId로 통일한다. 날짜를 바꿨는데 선택 단계가 해당 날짜에 없거나 이벤트가 철회됐으면 선택을 유효한 항목으로 재조정한다. 필터에서 빠진 일정을 계속 상세에 표시하려면 `현재 필터 밖의 선택`을 알려야 한다. 조용히 상세만 남는 상태는 피한다.

`오늘`·전장 오늘/내일·카운트다운은 실제 제품의 같은 시계 snapshot을 사용한다. 목업 고정 시각은 항상 목업임을 표시한다. 날짜만 확정과 시간까지 확정, 공식 원문과 운영자 해석을 서로 다른 상태로 표현한다.

## 4. 최종 화면 구성안

| 위치 | 내용 | 제한 |
| --- | --- | --- |
| 제목줄 | 이름, KR·KST, 작은 화면 버튼 | 큰 로고·소개 문구 없이 한 줄 |
| 상단 탭 | 달력 / 새소식 / 이용권 / 설정 | 전장 탭 없음. 운영자 화면은 기본 숨김 |
| 달력 요약 | 오늘 마감 수, 알림 선택 수, 다음 이용권 만료 | 한 줄. hover/클릭 상세 제공 |
| 달력 도구줄 | 월 이동·오늘, 월간/목록, 기간 표시 방식, 일정 추가 | 데이터 수집·운영 옵션 배치 금지 |
| 필터줄 | 종류, 알림 설정 일정, 검색 | 폭이 좁으면 두 줄, 글자 축소로 강제 한 줄 금지 |
| 달력 | 7열, 기간 막대 3행, 시점 일정, 더보기 | 일·주·월 경계에서 의미 보존 |
| 선택 상세 | 단계 강조, 기간·미정 조건, 알림 선택, 출처·검수 | 참여 완료를 자동 추정하지 않음 |
| 달력 하단 | 오늘 전장 / 내일 전장, 시즌·시리즈 시작 바로가기 | 필드 설명·랭킹·전술 기능 확장 금지 |
| 상태줄 | 현재 피드/오프라인·오래됨의 한 줄 요약 | 자세한 상태는 설정에서 확인 |

좁은 화면에서는 선택 상세를 아래로 쌓거나 별도 화면으로 여는 전환을 제공한다. 일정 제목이 긴 경우 UI가 달력 열 너비를 밀어내지 않게 한다. 기본 글꼴/배율은 사용자의 Dalamud 환경을 따르고, 별도 밀도 설정은 여백·행 수를 먼저 바꾸는 방식으로 설계한다.

## 5. 정보와 상태의 의미

| 보이는 상태 | 의미 | 허용하는 동작 |
| --- | --- | --- |
| 참여 진행 중 | 공식 참여 기간 안임 | 원문 열기, 해당 마감 알림 설정 |
| 참여 종료 | 참여 기간 경계를 지남 | 남은 수령 기간 안내. 개인 완료로 표시하지 않음 |
| 보상 수령 중 | 공식 수령 가능 기간 안임 | 수령 마감 알림·수동 체크 |
| 수령 확인 | 사용자가 이 프로필에서 직접 체크함 | 언제든 해제. 다른 계정/캐릭터에 자동 적용하지 않음 |
| 종료 일시 미정 | 시작/진행 사실은 있으나 종료 시각이 없음 | 상대 조건 표시, 날짜 확정 대기 |
| 일시 예정 | 공식 예고나 아직 변동 가능한 발표 | 예정 문구. 확정 알림과 구분 |
| 내용 정정 | 같은 ID의 의미 있는 기간/상태 변경 | 이전→새 값 1회 안내, 변경된 마감만 재예약 |
| 오프라인 | 현재 통신 실패·사용자 차단 | 마지막 정상 캐시와 개인 일정 사용 |
| 내용 재확인 필요 | 원문 수집이 오래 실패하거나 변경 후보가 미검수 상태임 | 이유·마지막 확인 표시. 개인 알림은 유지 |
| 전장 확인 불가 | 적용 범위·기준점·시퀀스 중 필요한 근거가 없음 | 공식 확인 경로 제공. 예시 필드를 실제값으로 노출하지 않음 |

“공식 확인” 한 배지는 날짜·시각의 모든 부분을 보장하지 않는다. 시작 시각을 점검 완료와 연결해 해석한 경우에는 해당 경계에 해석 근거를 붙인다. 한 이벤트의 시작은 확정, 종료는 미정일 수 있어 필드/경계 단위의 정밀도가 필요하다.

데이터 상태는 사용자가 복구할 수 있는 행동과 연결한다. `새로고침 중`, `새 데이터 없음`, `내려받기 실패·기존 데이터 사용`, `지원하지 않는 데이터 형식·플러그인 업데이트 필요`를 구분한다. 수집기가 원문을 못 읽은 상태를 클라이언트 새로고침 반복으로 해결할 수 있는 것처럼 안내하지 않는다.

각 원문 source의 수집 상태·미검수 변경·해당 규칙의 유효범위를 기준으로 경고한다. source의 전체 aggregate hash는 새 공지 하나만 추가돼도 달라지므로 개별 일정의 최신성 필수 조건으로 사용하지 않는다. 수집기는 내부 record별 승인 hash 비교 결과를 바탕으로 공개 health를 만든다. 클라이언트는 `completeCoverage === true`, `comparedContentRevision === activeContentRevision`, 최근 `lastSuccessAt`, 해당 일정에 영향을 주는 미검수 변경 없음, 규칙 유효범위를 함께 확인한다. 이 조건을 충족하면 검수 나이만으로 오래됨 경고를 만들지 않는다.

미검수 변경의 `affectedEventIds`는 `[]`이면 기존 일정에 영향 없는 신규 후보, `[ids]`이면 지정된 일정만 영향, `null`이면 범위 미확정으로 source 전체 재확인 필요를 뜻한다. 공개 hash는 진단용이며 이 영향 범위를 대신하지 않는다. 플러그인이 받은 `current.json`의 HTTP 304나 같은 일정 revision은 이 기기의 확인 시각만 갱신할 수 있으며 운영자의 내용 검수 사실을 새로 만들지 않는다. 이 상태 정책은 [데이터 파이프라인](../architecture/DATA-PIPELINE.md)과 합의한 제품 기준이다.

## 7. 구현 Go / No-go 기준

### 이용권과 개인 상태

- **Go:** 로컬 계정 별칭 한 개를 사용자가 편집하고 확인한 종료 일시를 저장한다. 현재 목업은 이 범위다.
- **No-go:** 실제 계정 식별·여러 계정 연결을 구현하지 않고 “모든 캐릭터 자동 공유 완료”라고 표시한다.
- **No-go:** 보상 이용권 공지를 읽었다는 이유만으로 개인 종료일을 자동 연장한다.
- **Go 조건:** 날짜만 아는 입력은 date-only 모델과 표시·날짜 알림을 구현한 뒤 제공한다. 미확인 시각에 23:59를 자동 삽입하지 않는다.

### 전장 오늘/내일

- **Go:** 유효한 KR 규칙의 시간대·날짜 경계·sequence·기준점·유효기간을 확인한 범위에서 두 날짜를 계산한다.
- **No-go:** 현재 게임 버전에 맞는지 모르는 기준점 하나 또는 글로벌 일정을 근거로 실제 필드 이름을 확정한다.
- **Go 조건:** 적용 규칙이 바뀌는 자정·patch 경계에서 오늘과 내일이 서로 다른 규칙을 사용할 수 있어야 한다. 둘 중 하나가 미확인이면 그 날짜만 미확인으로 표시한다.

### 반복 일정

- **Go:** 각 반복 일정별 공식 근거와 timezone, 지역, local reset time, 발효일을 등록하고 날짜 경계를 검증한 뒤 도입한다.
- **No-go:** 전장 0시 변경을 모든 일일 콘텐츠에 적용하거나, 한국/글로벌의 주간 초기화를 공유 상수로 둔다.
- **Go 조건:** PC 시간대가 달라도 같은 KR 경계를 계산하고, 미래 패치의 규칙 교체·예외 점검과 중복 생성을 처리한다. DST를 쓰는 지역은 해당 timezone 규칙을 포함한다.

### 알림과 완료 체크

- **Go:** 게임이 실행되는 동안 로컬 알림을 제공하고, 닫힌 동안 발송하지 못한다는 제한을 UI에 표현한다.
- **No-go:** 종료된 공개 일정 상태를 사용자의 참여 완료·수령 완료로 취급한다.
- **Go 조건:** 로컬 체크는 프로필+event+phase ID에 연결하고 수집 정정과 독립적으로 보존한다. 철회·재개·기한 연장 때 체크를 지울지의 규칙을 명시한다.

## 10. 참고 근거

- 현재 제품 요구·화면: [화면 명세](../SCREENS.md), [브리핑](../BRIEFING.md).
- 관찰한 코드: `mockup/app.js`의 `agendaHTML`, `detailHTML`, `renderCompact`, `frontlineHTML`, `milestonesHTML`, `dataPage` 및 `mockup/calendar-layout.js`, `mockup/compact.css`. 해당 함수는 후속 수정으로 달라질 수 있다.
- HTML 탭의 역할·선택 상태·방향키·Home/End 동작은 [W3C APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)을 참고한다. ImGui는 HTML ARIA API를 그대로 사용하지 않으며, 동등한 탐색·focus 동작을 별도로 검증한다.
- 중요한 선택·focus·조작 표시를 배경과 구별하는 색 대비 목표는 [W3C Non-text Contrast 설명](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)을 참고한다. 이것을 게임 플러그인의 규정 준수 인증으로 표현하지 않는다.
