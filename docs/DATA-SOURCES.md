## HTTP 관찰 기록

PowerShell `Invoke-WebRequest`로 다음을 확인했다. 길이는 그 시점의 문자열 길이이며 재현 시 변경될 수 있다.

| URL 경로 | 응답 | 관찰 |
| --- | --- | --- |
| `/news/event` | 200 / 약 47.7K 문자 | HTML에 이벤트 기간 존재 |
| `/news/notice` | 200 / 약 47.1K 문자 | 게시물 링크·본문 접근 가능 |
| `/news/patchnote` | 200 / 약 97.7K 문자 | 패치노트 목록 접근 가능 |
| `/robots.txt` | 오류 페이지로 이동 후 200 | 최종 `/error/notfound?v=1`; 유효 robots 규칙을 얻지 못함 |

세 목록에 `application/ld+json` 스크립트는 관찰되지 않았다. 이것만으로 숨겨진 API·RSS가 없다고 단정할 수는 없다. 개발자용으로 문서화된 KR 뉴스·이벤트 API는 이번 조사에서 확보하지 못했다. 비공개 내부 API 호출을 먼저 설계하지 않고 공개 HTML과 수동 입력을 우선한다.

관찰한 HTML 단서는 이벤트 링크 `/news/event/view/{id}`, 기간 컨테이너 `.period`, 단계 `.term .lbl`, 날짜 `time[datetime]`, 공지 상세 `.view_box`다. **안정성 보장 선택자가 아닌 최초 파서 후보**다. 이벤트 페이지가 개별 프로모션 주소로 리디렉션될 수 있다. 링크 ID는 원래 게시물 ID로 보존하고 최종 주소를 별도로 저장한다.

## 실제 사례가 요구하는 데이터 규칙

1. [헬스케어 프로그램](https://www.ff14.co.kr/events/2026/A1013): 목록 기준 참여는 2026-11-11 23:59, 수령은 2026-12-09 23:59 종료. 같은 이벤트의 서로 다른 단계다. 상세의 참여 실적은 로그인 영역이므로 수집하지 않는다.
2. [기간 변경 공지 3153](https://www.ff14.co.kr/news/notice/view/3153): 이벤트 기간·보상 수령 기간이 바뀌고 원 이벤트 페이지 반영이 뒤늦을 수 있음을 알린다. 정정 출처가 필요하다.
3. [마법자판 난타전](https://www.ff14.co.kr/events/fun/special/keybound_brawler): 목록의 종료 조건이 V8.0 업데이트 전까지다. `endsAt: null`과 `endCondition`을 유지한다.
4. [점검 완료 변경 공지 3162](https://www.ff14.co.kr/news/notice/view/3162): 2026-11-10 점검이 12:00~18:15에 완료됐고 시즌 22 시작을 알린다. 완료 공지의 적용 사실을 이전 계획과 연결한다. 시즌의 정확한 개방 시각은 이 공지의 점검 완료와 연결한 해석임을 기록한다.
5. [시즌 22 전환](https://www.ff14.co.kr/news/notice/view/3160): 이전 시즌 보상 기한을 다음 시즌 종료에 연결한다. 이를 임의의 날짜로 치환하지 않는다.
6. [시리즈 12 전환](https://www.ff14.co.kr/news/notice/view/2947): 시즌과 다른 9/8 시작일을 확인했다. 시리즈 종료는 8.0 점검 시작 전이다. 신규 시작은 같은 모델로 추가한다.
7. [7.5 전장 순환](https://www.ff14.co.kr/news/notice/view/2865): 변경 후 8일 순서를 본문 표에서 확인했다. 기준일은 표에 없어 실제 오늘/내일 계산에는 추가 확인이 필요하다.

## 수집 권장 순서

1. 로그인·쿠키 없이 목록을 낮은 빈도로 가져온다. 구체적인 정책 확인 전에는 수동 운영으로 시작한다.
2. 첫 회에는 진행 중 이벤트 전체와 최근 공지를 확인한다. 이후 최근 목록을 겹쳐 읽고, 진행 중 이벤트는 종료/정정 확인까지 추적한다. 공지 페이지 추가 탐색은 ‘마지막 확인 ID’를 만날 때까지, 상한에 도달하면 검수 경고를 낸다.
3. 전체 HTML을 공개 저장하지 않고 ID·짧은 사실 요약·기간·출처·본문 해시를 후보 파일에 저장한다. 파서 회귀용 fixture는 최소 부분만 남기며 이용 조건을 재검토한다.
4. 제목의 ‘할인’ 한 단어로 종류를 확정하지 않는다. 웹/인게임/시즈널/판매·수령 대상, 지역, 확정 정도를 검토한다.
5. 날짜가 배너 이미지에만 있으면 운영자가 입력하고 `method: manual`을 붙인다. OCR/LLM 결과는 자동 게시하지 않는다.
6. 403·429·로그인·CAPTCHA·오류 페이지는 중단한다. 인증·우회·재시도 폭주를 구현하지 않는다. 수동 출처 등록으로 전환한다.

## 기술·운영 근거

- [Dalamud 제한](https://dalamud.dev/plugin-publishing/restrictions/): PvP 정보 범위와 심사 불확실성을 먼저 고려한다. 일정 안내의 허용을 이 문서만으로 단정하지 않는다.
- [Dalamud SamplePlugin](https://github.com/goatcorp/SamplePlugin): 신규 플러그인의 기본 서비스·설정·명령 등록 참고. 실제 착수 때 현재 SDK와 KR 호환성 확인.
- [GitHub schedule 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule): 예약 실행은 지연·누락될 수 있고 공개 저장소는 장기간 활동이 없으면 예약이 비활성화될 수 있다. 따라서 수동 실행과 마지막 수집 시각 감시를 제공한다.

웹 원문 전체·배너·게임 이미지는 이번 산출물에 복사하지 않았다. 제목·짧은 사실·원문 링크 위주로 다루고, 향후 외부 데이터 도입 때 URL·revision·라이선스·가공 내역을 기록한다.
