# 0.2 화면 재설계: 10회 수정·검토

2026-11-13. 사용자가 제공한 실제 게임 화면11장과 사용 목적을 기준으로 화면 구조를 다시 만들었다. 사용자가 지적한 항목 외에도 각 변경으로 생기는 상태·입력·크기 문제를 함께 검토했다. 아래는 같은 검사 명령을10번 실행했다는 뜻이 아니라, 실제 설계 변경과 후속 검토를10개 회차로 기록한 것이다.

## 목표와 판단 기준

일정을 열어 이름과 기간을 알고 공식 링크로 이동할 수 있어야 한다. 현재 보고 있는 월이 분명하고 달력의 날짜·종류·시각이 정확해야 한다. 설명과 자료 수, 상시 비어 있는 패널 때문에 계획 영역을 줄이지 않는다. 이용권은 사용자가 이름을 지어 관리하는 일정이 아니라 서비스 종류와 남은 기간을 관리하는 항목이다.

## 확인한 사용 흐름

- 2027년2월 이동 →19일 또는 표식 클릭 → 얼리·특전 구매 마감·CE 예약 마감3건 → 각각 공식 링크.23일 정식 출시의 날짜 단위 정밀도는 유지한다.
- 2026년11월10일 → 게임 서버 점검과 실제 패치/PvP 일정. 공지 게시일·PC방 점검은 표시 선택으로 되살릴 수 없다.
- 새소식 검색·분류 → 링크 클릭. 달력 종류나 선택 날짜가 바뀌지 않는다.
- 설정 → 정액제 등록90일 → 날짜 미리보기 → 저장. 남은30일이 있는 이용권에90일 충전하면 기존 만료일에서90일 늘어난다. 이름을 요구하지 않는다.
- 시각 지정 개인 일정은 항목 알림과 전역 채팅 알림을 선택할 수 있다. 날짜만 아는 항목은 시각 알림을 만들지 않는다.
- 월 휠: 분수 입력 누적, Ctrl/팝업/영역 밖 차단,2020~2100 경계. 팝업 뒤의 월이 움직이지 않는다.

## 증거와 한계

Core118, Infrastructure116, Model71, native UI300, 수집96, CLI23으로724개 검사. 별도로 한국어 리소스222개의 형식과 lookup을 검사한다. native UI는620×480·1060×720·1320×1050 및1/1.5/2배율에서 실제 MainWindow를 사용한다. 입력 검사는 실제 ImGui 문자 이벤트와 클릭/휠 이벤트를 사용한다. geometry CSV는 `.preview/imgui-checks/`에 남긴다.

`dotnet run --project tests/DuckbillCalendar.ImGui.Checks -- --preview 1060 720 midnight`로 실제 DrawData를 CPU로 렌더링한다. `cloud`, `graphite`, 마지막 scale 인수를 지원한다. 월/출시월/날짜 팝업/새소식/설정/이용권/개인 폼을 생성한다. 전장 미리보기 데이터는 실제 공개 응답을 고정한 fixture이며 화면 촬영 중 네트워크는 사용하지 않는다.

실제 전장 수신은 `dotnet run --project tests/DuckbillCalendar.Infrastructure.Checks -- --frontline-live`로 별도 확인한다. 이 명령은 공개 월만 요청한다.

게임에서 플러그인을 자동 다시 로드하거나 조작하지 않았다. 게임 GPU·게임 글꼴·Dalamud 배율·알림 전달·플레이어의 실제 과제 수행은 이 검사로 완료되었다고 주장하지 않는다. 아주 작은 창에2배 글자를 쓰면 월 전체를 동시에 표시할 수 없으므로 달력 내부 스크롤을 제공한다. 일반 창에서 상시 빈 상세를 두는 것과 구분한다.

이 문서는 이전 PRODUCT-UX-REVIEW / INTERACTION-DESIGN / SCREENS의 화면 구성보다 우선한다. 데이터 경계·저장·출처의 기존 계약은 유지한다.
최종 교차 검토에서 저장/취소를 작은 화면의 스크롤 폼 바깥에 고정하고 팝업을 현재 viewport 안에 다시 배치했다. 달력의 인접 월 날짜를 클릭하면 월 제목도 함께 이동한다. 제목 크기를 키운 뒤 호출자의 글자 배율을 복원해 외부 배율을 유지한다.
