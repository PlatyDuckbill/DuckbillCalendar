# 달력의 정보 구조와 상호작용 재설계

2026-11-13. 사용자 화면, 현재 MainWindow/CalendarModel, 실제96건 저장본을 검토한 설계안이다. 사용자 인터뷰나 실제 사용성 테스트를 수행했다고 주장하지 않는다. 아래 판단은 관찰 가능한 화면·데이터·코드에 근거한 설계 가설이며, 마지막의 행동 기준으로 검증한다.

## 1. 화면이 해결해야 하는 질문

게임 내 달력을 여는 목적은 자료의 존재를 확인하는 데 그치지 않는다. ‘언제 무엇을 할 수 있고, 무엇을 언제까지 해야 하며, 지금 보고 있는 날짜에서 어떤 행동을 해야 하는가’를 짧은 시간에 판단해야 한다.

| 사용 의도 | 첫 화면이 답할 내용 | 다음 행동 |
| --- | --- | --- |
| 오늘 놓치는 것이 있는가 | 오늘 시작·마감, 진행 기간 중인 일정의 구분 | 해당 단계 상세 또는 원문 열기 |
| 2027년2월을 계획하고 싶다 | 그 달의 날짜 경계와 순서 | 날짜 선택 → 해당 날의 모든 단계 |
| 얼리와 정식 출시를 확인한다 | 서로 다른 날짜·시각 정밀도·이용 조건 | 정확한 마커/단계 선택 |
| 오래 진행하는 혜택을 찾는다 | 종료가 정해진 이벤트와 구별된 탐색 목록 | 제목 검색·원문 확인 |
| 개인 이용권이 언제 끝나는가 | 정확한 만료일과 잔여 기간 | 수정 또는 개인 알림 선택 |

‘모든 데이터를 담기’와 ‘모든 데이터를 같은 화면에 펼치기’는 서로 다른 요구다. 자료는 유지하되 화면의 각 영역은 담당하는 질문을 하나로 제한한다.

## 2. 현재 결함의 원인

1. **시간 기준이 세 개다.** 2027년2월 그리드 옆에 오늘 기준의2026년12월 마감과2026년11월13일 선택 상세가 함께 나타난다. 영역 제목이 이 차이를 설명하지 않아 사용자가 각 항목의 관련성을 다시 계산해야 한다.
2. **달력 마커가 자료 제목을 복제한다.** 좁은 칸에 ‘앞서 해보기 시작 · V8.0 백은의 탐구자 앞서 해보기’를 넣어 정보가 중복되고 실제로 필요한 시각과 행동이 잘린다. 공간을 넓히는 것만으로 해결되지 않는다.
3. **데이터 상태와 이용 의도가 섞였다.** 종료 미정12건에는2015년부터 목록에 남아 있는 혜택, 현재 게임 내 행사, 조건형 시리즈 종료가 섞여 있다. 모두 같은 ‘미정’ 목록에 두면 긴급한 다음 발표처럼 보인다.
4. **선택의 결과가 약하다.** 날짜 셀, +N, 행사, 단계의 클릭이 같은 상세 패널을 공유하지만 현재 무엇을 선택했는지 일관된 제목·선택 표현이 없다. 한 행사에 여러 단계가 있을 때 다른 단계의 날짜까지 화면을 차지한다.
5. **조작 빈도와 화면 비중이 반대다.** 표시 종류와 보기 설정은 매번 변경하는 기능이 아닌데 상단 높이를 크게 점유한다. 반면 매번 읽어야 하는 날짜별 일정의 제목은 축약·숨김된다.

이 진단에 따라 순서를 바꾸어야 한다. 우선 맥락과 선택 상태를 정리하고, 그다음 영역 크기·표시 밀도를 조정한다.

## 3. 단일 기본 화면의 역할 분리

상단 가로 탭은 달력/새소식/이용권/설정을 유지한다. 별도 PvP 탭과 별도 작은 화면 창은 만들지 않는다. 작은 화면 명령·버튼·윈도는 제거한다. 창 크기에 따른 재배치는 같은 화면의 반응형 동작이다.

### 기본 구조

```text
달력 | 새소식 | 이용권 | 설정

‹ 2027년2월 ›  오늘                 검색  캘린더8/9  보기  +일정
주요 출시 · 2/19 18:00 얼리 · 2/23 정식                 날짜로 이동

┌──────────────────────────────┬──────────────────────┐
│                              │ 이 달 일정           │
│         월간 달력            │ 2/19 금              │
│                              │ 18:00 얼리 액세스    │
│                              │ 18:00 예약 구매 마감 │
│                              │ 2/23 화              │
│                              │ 정식 출시 · 시각미정 │
└──────────────────────────────┴──────────────────────┘
전장: 오늘 … / 내일 …            수집 상태 · 항목별 출처 확인
```

- **달력**: 현재 월의 날짜와 시작/마감/시점 분포를 보여 준다.
- **agenda**: 현재 월·선택 날짜·선택 단계 중 현재 맥락 하나를 설명한다. 전역 다가오는 일정을 동시에 섞지 않는다.
- **주요 출시 안내**: 사용자가 특히 중요하게 요청한 얼리/정식 출시의 전역 기준점이다. 달력과 다른 달이면 ‘주요 출시’라는 별도 명칭과 이동 행동으로 관련성을 명시한다. 여기에 판매·대회 마감을 무작위로 더하지 않는다.
- **진행중·종료미정 탐색**: 일반 월간 달력 아래에 무제한 펼치지 않는다. ‘일정 목록’ 보기 또는 별도 목록 섹션에서 접근한다. 이름과 검색을 유지해 정보가 사라지지 않게 한다.
- **수집 시각**: 일정 날짜보다 낮은 시각적 우선순위를 둔다. 전체가 동시에 검증됐다는 의미로 쓰지 않고 상세에서 항목별 관측 시각을 제공한다.

### 도구의 배치

년월/이전/다음/오늘은 한 그룹, 검색/표시 종류/보기/추가는 다른 그룹이다. 기본 상태에서 설정용 설명 문단을 표시하지 않는다.

종류별 체크박스는 사용자 요구대로 유지한다. ‘캘린더8/9’를 눌러 펼치는 동일한 체크리스트를 모든 폭에서 제공할 수 있다. 현재 선택 수와 ‘공지 게시 숨김’ 같은 주요 조건은 버튼/요약에 남긴다. 이는 중요한 일정을 숨기는 방식이 아니라, 낮은 빈도의 표시 관리 도구와 높은 빈도의 일정 읽기를 분리하는 방식이다. 체크박스 패널을 항상 열어 둘 수 있는 선택을 제공하더라도 본문 높이를 무제한 확장하지 않는다.

목록/시작·종료/기간 막대 같은 표시 옵션은 ‘보기’에 모은다. 기본 시작·종료 마커와 선택적 긴 막대, 저장된 종류 선택을 유지한다. 전체 선택·모두 숨기기 뒤에는 현재 표시 조건과 빈 상태를 분명히 알려 준다.

## 4. 명시적 선택 상태

| 상태 | 진입 | agenda 제목과 내용 | 선택 표현 |
| --- | --- | --- | --- |
| Month | 이전/다음/휠/년월 직접 이동 | ‘이 달 일정’, 현재 월의 시작·마감·시점만 날짜순 | 날짜 선택 강조 없음 |
| Day | 날짜 셀 또는 +N 선택, 오늘 버튼 | ‘2월19일 금요일’, 시작/마감/진행중을 구분 | 선택한 셀 배경/테두리 |
| Event | 마커 또는 agenda 단계 행 선택 | 선택 날짜 → 선택 행사·단계 상세 | 해당 셀과 해당 행 강조 |

월을 바꾸면 과거 달의 event/phase 선택을 끌고 가지 않는다. 모델에서 SelectedDate를 보관해야 하더라도 target월로 날짜를 맞추고 UI는 Month 상태를 사용한다. 처음 연 날짜와 무관한 ‘선택 날짜11월13일’이2월 화면에 남으면 안 된다.

‘오늘’은 오늘의 Day 상태로 돌아간다. 날짜를 선택했지만 시작·마감이 없으면 ‘이 날 시작·마감 없음’이라고 답하고, 진행중 목록이 있으면 별도로 구분한다. 무관한 전역 일정을 가져와 빈 곳을 메우지 않는다.

Event 상태에서는 선택 phase를 먼저 보여 준다. 상단은 전체 제목, 종류·상태, 선택한 시작/마감·시각, 원문 버튼이다. 다른 phase는 ‘관련 단계’ 목록에서 선택한다. 해당 단계의 날짜를 누르면 달력과 선택 날짜가 함께 바뀐다. 행사 선택과 phase/edge 선택을 구별해야 마감 클릭이 시작일 상세로 바뀌지 않는다.

## 5. 셀의 시각 문법

기간은 기본으로 시작·종료 날짜에만 표시한다. 각 마커는 **행동/시점 + 짧은 표시명**을 쓴다. 원제·원문은 보존하고, 달력에 한해 표시용 별칭을 사용한다.

| 실제 자료 | 달력용 표시 예 | agenda/상세 |
| --- | --- | --- |
| V8.0 백은의 탐구자 앞서 해보기 시작 | `18:00 얼리` | 전체 제목·앞서 해보기·2027-02-19 18:00 KST |
| V8.0 정식 출시 | `8.0 출시` | 2027-02-23·시각 미발표 |
| CE 사전예약 종료 | `CE 예약 마감` | 종료일·정확한 종료 시각·대상 조건 |
| CCRC 신청 마감 | `신청 마감` | 대회명·참가신청 phase·날짜 정밀도 |
| 개인 이용권 종료 | `이용권 만료` | 사용자 입력 제목과 만료일 |

짧은 이름은 날짜를 추론하거나 원문 제목을 변경하는 기능이 아니다. 알려진 curated 항목은 관리된 표시명을 사용하고, 다른 항목은 중복 접두를 줄인 원제+말줄임을 사용한다. hover는 전체 제목과 phase를 제공하지만 핵심 행동을 읽는 데 hover가 필수가 되면 안 된다.

기본 셀은 날짜 행 + 마커2행 + overflow 행동을 목표로 한다. 공간이 충분한 경우3행까지 허용한다. 적은 일정 때문에 주 높이가 불필요하게 커지거나, 일정이 몰린 날 때문에 전체 월이 길어지지 않게 한다. overflow는 `+2개`처럼 읽을 수 있는 행동이며, 클릭하면 Day agenda에 숨겨진 항목까지 모두 표시한다. overflow로 표현한 일정은 누락이 아니다.

한 날짜에 시작·마감이 여러 개라면 모든 자료를 단일 긴 제목으로 합치지 않는다. 데이터에 명시된 관련 관계가 있을 때만 표시 그룹으로 묶는다. 예컨대 CE 예약 종료와 예약 특전 대상 구매 종료를 단순 문자열 유사도만으로 제거하면 안 된다. 공통 구매 행동으로 묶을 경우에도 상세에서 두 근거·조건을 유지한다.

### 색·강조의 역할

- 종류 색은 체크박스, 작은 점/좌측 선, 보조 표시에 연결한다. 모든 행을 강한 채색 카드로 만들지 않는다.
- 선택 상태는 종류 색과 독립된 하나의 강조색을 사용한다. 오늘은 금색 날짜 숫자, 선택 날짜는 파란 셀 테두리로 구별한다. 월 개요 상태에서는 임의 날짜를 선택한 것처럼 강조하지 않는다.
- 마감·미정·재확인은 색만으로 설명하지 않는다. `마감`, `시각 미발표`, `재확인` 같은 문구를 함께 사용한다.
- 기본 Dalamud 폰트와 스케일을 유지한다. 새 폰트/굵기 의존보다 정렬·정보량·간격으로 위계를 만든다.

## 6. 확실성과 일정 타입

| 데이터 상태 | 표현 원칙 |
| --- | --- |
| 정확한 시각 발표 | 날짜와 KST 시각을 표시한다. 날짜그룹 안에서는 반복 연도/월을 줄인다. |
| 날짜만 확정 | 달력은 날짜 마커, agenda는 필요 시 `시각 미발표`. 상세에서는 정밀도를 반드시 설명한다. |
| 예정 날짜 | `예정`을 붙인다. 확정과 같은 문법으로 무표식 표시하지 않는다. |
| 알려진 기간·종료 미정 | ‘진행중·종료미정’ 탐색으로 접근한다. 끝 날짜를 만들지 않는다. |
| 조건형 종료 | ‘8.0 점검 시작 전’ 등 조건 자체를 보여 준다. 정식 출시일이나 얼리 일시로 치환하지 않는다. |
| 원문 변경·조회 실패 | 기존 날짜와 함께 `재확인 필요`. 성공적인 HTTP 조회와 날짜 의미 검증을 구별한다. |
| 공지 게시 | 실제 실행 일정과 구분한다. 새소식에 남고 달력 표시 여부는 사용자 선택을 따른다. |

오래 목록에 남아 있다는 이유만으로 ‘상시’라고 확정하지 않는다. ‘무료 플레이 혜택’, ‘GARO’, ‘구부는 탱커를 좋아해’는 장기 목록에 있지만 공식 종료 선언을 추론할 수 없다. 기간을 모르는 자료의 기본 목록 명칭은 `진행중·종료미정`이 적합하다. 실제 새로운 일정의 날짜가 발표되지 않은 `미발표`와 구분한다.

시리즈12의 ‘8.0 점검 시작 전’과 오래된 혜택을 한 긴급 미정 목록에 섞지 않는다. 전자는 보상 수령 행동과 연결되므로 조건 마감 안내, 후자는 탐색 대상이다.

## 7. 밀도와 반응형 수치

수치는 기본 폰트17px 기준이며 실제 폰트 크기에 비례한다. 창을 강제로 자동 확대하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 외곽/영역 간격 | 외곽8~12px, 큰 영역12px, 같은 정보끼리4~6px |
| 도구 행 | 약28~32px, 부족하면 의미 단위별 두 행. 임의의 widget 한 개만 따로 줄바꿈하지 않음 |
| agenda 폭 | 넓은 화면280~340px, 달력 나머지. 1300px에서 우측을 불필요하게 더 늘리지 않음 |
| 주 높이 | 기본82px 전후, 날짜와 최대3개 마커 기준. 정확히3건이면 전부 보이고 초과할 때만 overflow 행을 예약. 막대 lane이 추가되면 그만큼 높이 확장 |
| agenda 행 | 원제목의 자연 줄바꿈과 보조 시각/행동을 함께 측정해 높이를 결정. 왼쪽 종류 선과 텍스트는8px 분리 |
| 상세 제목 | 최대2~3행 자연 줄바꿈. 원문 버튼은 첫 화면 내1회 행동으로 접근 |
| 리스트 | 자체 스크롤로 높이 제한. 현재 월을 탐색하는데 종료미정 목록 길이가 창 전체를 늘리지 않음 |

980×660에서는 월간 달력+우측 agenda가 기본이다. 1300px에서는 더 넓어진 셀에 마커 표시명을 자연스럽게 사용하되 agenda는 최대 폭을 유지한다. 760px 또는 큰 배율의 월 상태에서는 달력에 집중하고 월 개요는 상단 ‘월 목록’으로 연다. 날짜/일정 선택 시 같은 창 본문을 일간 agenda/상세로 전환한다. `이 달 일정 보기`와 `일정 목록` 복귀 행동을 명시한다. 별도 ‘작은 화면 모드’ 창은 만들지 않는다. 물리적으로 모든 행이 들어가지 않는 조건에서는 본문 스크롤을 제공하고 잘린 내용을 정상 상태로 간주하지 않는다.

마우스 휠의 월 이동은 날짜 격자에만 적용한다. agenda/상세의 휠은 목록 스크롤이어야 한다. 날짜 격자를 scrolling canvas와 동일한 의미로 사용하지 않는다.

## 8. 실제 자료로 확인할 두 흐름

### 2027년2월 출시 계획

1. 년월에서2027년2월로 이동한다. agenda는 ‘이 달 일정’이 되며11월 선택을 지운다.
2. 그리드에2/19 `18:00 얼리`, 예약 구매 마감,2/23 `8.0 출시`가 서로 다른 마커로 보인다.
3. 2/19 또는 +N을 누르면 그 날짜의 얼리 시작과 구매 마감을 모두 확인한다.
4. 얼리 행을 누르면 앞서 해보기 phase·권한 조건·18:00 KST·원문을 확인한다. 정식 출시와 혼동하지 않는다.
5. 2/23은 날짜 확정/시각 미발표로 보이며 임의의00시 카운트다운은 없다.

### 오늘의 참가/마감 확인

1. 오늘 버튼으로 오늘 Day 상태로 돌아간다.
2. 오늘의 시작/마감이 먼저 보이고, 기간 중인 알려진 행사는 별도 그룹이다.
3. 장기 혜택은 ‘진행중·종료미정’ 목록을 열어 검색한다. 단순히 오늘 안에 마감할 자료처럼 노출되지 않는다.
4. 시리즈 보상 수령의 조건형 종료는 조건 문구와 원문으로 확인한다. 불확실한 날짜를 확정 일정으로 바꾸지 않는다.

## 9. 구현·검증 우선순위

1. Month/Day/Event 상태와 agenda projection을 먼저 정리한다. `MonthEvents`는 종료 미정 장기 자료까지 포함하므로 월 경계 agenda에 그대로 쓰지 않는다. 해당 월의 phase 시작/종료/point 경계를 따로 계산한다.
2. compact 창·명령·버튼을 제거한다. 남은 표시 옵션·체크박스의 의미와 저장 상태를 유지한다.
3. 짧은 마커 문법과 하루 최대2~3행, +N→Day 전체 목록을 구현한다.
4. 단일 agenda와 phase 중심 상세, 원문1회 행동을 연결한다.
5. 전역 출시 안내와 장기/미정 탐색을 별도 역할로 정리한다.
6. 마지막으로 크기·색·간격과 다양한 배율의 bounds를 검증한다.

성공 기준은 ‘검사 개수 증가’가 아니다. 2027년2월로 이동했을 때 과거 선택 날짜가 나타나지 않고,2/19의 모든 행동을 한 번 선택해 읽으며, 출시 개장 시각이 미발표임을 알 수 있고, 종료미정 탐색이 월간 화면 높이를 결정하지 않는지 확인해야 한다. 네이티브 geometry 검사는 잘림·폭·스크롤 회귀를 검증하는 보조 수단이며 실제 게임에서 읽고 판단하는 사용성 확인을 대신하지 않는다.
