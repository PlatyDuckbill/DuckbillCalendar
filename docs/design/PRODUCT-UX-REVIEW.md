# 게임 안에서 판단할 수 있는 일정 도구

2026-11-13. 제공된 2027.02 게임 화면, 실제 MainWindow/CalendarModel, 번들 96건을 검토한 제품·UX 설계안이다. 사용자 조사나 새 화면의 실기 검증을 수행한 것으로 해석하지 않는다. 아래 행동 우선순위는 대화에서 도출한 설계 가설이며 구현 후 과제로 확인한다.

## 제품의 역할

이 플러그인의 가치는 수집한 자료 수보다, 게임 중 짧게 열어 **놓칠 시점과 계획할 날짜를 찾고 다시 게임으로 돌아갈 수 있는가**에 있다. 월간 달력은 공간적 계획 도구이고, 일간 목록은 그날의 의미를 읽는 도구다. 출처·공지 원문·불확실한 기간은 판단을 뒷받침하는 정보다. 이 세 층을 같은 크기의 목록으로 한 화면에 펼치면 데이터가 정확해도 결정하기 어렵다.

사용자 요구는 유지한다. 상단 가로 탭, 종류별 다중 체크박스, 시작·종료 기본 표시, 선택 가능한 기간 막대, 오늘/내일 전장 요약을 유지한다. 별도 PvP 탭은 만들지 않는다. 작은 화면 기능은 명시적 요청대로 제거하되 기본 창의 작은 너비와 큰 글자 배율 대응은 유지한다. 반응형 단일 창과 별도 작은 창은 다른 요구다.

문제는 단순히 목록을 접거나 여백을 줄이는 것이 아니다. **현재 무엇에 대한 답을 보여 주는지**를 먼저 명확하게 해야 한다.

## 행동과 우선순위

| 여는 이유 | 첫 화면이 답할 질문 | 주 행동 | 완료 상태 |
| --- | --- | --- | --- |
| 마감 확인 | 가까운 확정 마감이 있는가 | 날짜/마감을 열어 조건 확인 | 마감 일자·시각 또는 미발표 상태를 구별함 |
| 특정 월 계획 | 그달 언제 무엇이 시작/끝나는가 | 휠·년월 이동 → 날짜 선택 | 현재 월의 시작·종료/출시를 비교함 |
| 오늘 할 수 있는 일정 탐색 | 오늘 진행 중이거나 전환되는 것은 무엇인가 | 오늘 → 일간 목록 | 참여 여부를 스스로 판단할 정보에 도달함 |
| 확장팩·패치 확인 | 얼리와 정식 출시가 각각 언제인가 | 주요 발표 바로가기 → 해당 날짜 | 두 시점과 시간 정밀도를 혼동하지 않음 |
| 이용권 관리 | 내 이용권이 언제 끝나는가 | 이용권 → 수정 | 입력한 종료일과 남은 기간을 확인함 |

일정 진행 중이라는 사실과 사용자가 참여 자격을 갖췄다는 판단은 구분한다. 구매 여부·레벨·참가 자격을 모르는 공개 일정에 ‘해야 할 일’이나 ‘참여 가능’을 단정하지 않는다. 확정된 개인 만료와 가까운 확정 마감은 우선 주의를 줄 수 있지만, 미정 조건만으로 긴급 경고를 만들지 않는다.

## 단일 창의 정보 구조

### 1. 탐색 줄

현재 월, 이전/다음, 오늘, 년월 직접 이동을 가장 명확한 탐색 묶음으로 둔다. 검색과 ‘표시할 캘린더’는 내용 도구로 구분한다. 현재 선택 개수/필터 활성 상태를 읽을 수 있게 하고 종류별 체크박스는 계속 직접 조절할 수 있어야 한다. 항상 전체9개를 가장 큰 제목 블록으로 펼쳐 놓을 필요는 없지만, 한 번 열고 닫을 수 있고 선택 상태를 숨기지 않는다.

목록/달력 모드는 같은 월과 같은 필터를 유지한다. 기간 막대는 표시 방법 옵션이며 일정 종류 선택과 다른 개념이다. 기본은 시작/종료이고, 옵션을 켰을 때만 연속 막대를 사용한다. 일정 추가는 눈에 보이는 단일 행동으로 유지한다.

### 2. 월간 캔버스

날짜 숫자 → 행동 표식 → 짧은 일정명 순으로 읽힌다. 색은 종류에만 일관되게 사용한다. 시작/마감/얼리/출시는 짧은 텍스트로 구분해 색에만 의존하지 않는다. 오늘과 선택 날짜도 다른 상태로 보이게 한다.

셀에 전체 제목을 넣는 것을 목표로 하지 않는다. 충분한 폭에는 `18:00 · 얼리`와 짧은 명칭을, 작은 폭에는 `얼리` 같은 핵심 역할을 우선한다. 시각을 생략한 셀도 날짜를 누르면 일간 목록에서 전체 시각을 읽을 수 있어야 한다. hover는 보조 확인 수단이며 유일한 전체 정보 접근 수단이 아니다.

정해진 픽셀 높이를 맞추려고 모든 날을 한 항목으로 제한하지 않는다. 가용 글자 크기/너비에 따라2~3개의 짧은 표식을 표시하되 셀 높이를 끝없이 늘리지 않는다. +N은 그날의 전체 목록으로 연결한다. 기본 창에서 일정을 읽을 수 있는 최소 높이를 지키고, 불가능한 큰 배율·작은 높이에서는 한 창 안의 스크롤/일간 전환을 제공한다. 모든 크기에서 같은 정보를 동시에 펼치겠다고 약속하지 않는다.

### 3. 날짜의 답을 보여 주는 패널

월 탐색의 기본 상태는 그달 경계 목록이며 날짜 선택 후에는 `2월19일 · 3건` 같은 일간 목록이다. 시작/마감/진행 중을 구분하고 시각이 있으면 정렬한다. 날짜만 발표된 항목은 시각이 없다는 사실을 별도로 표시한다. 기존처럼 ‘선택한 날의 항목’을 먼저 접은 다음 또 ‘상세를 선택하세요’를 노출하지 않는다.

일간 목록의 항목을 명시적으로 선택하면 같은 패널 안에서 상세로 전환한다. 날짜 제목과 목록으로 돌아가는 경로를 유지한다. 상세는 행동과 기준 시각, 참여/구매 조건, 공식 원문 순으로 구성하고 내부 진단은 마지막에 둔다. 아무 일정이나 자동으로 상세 선택해 사용자의 선택처럼 보이게 하지 않는다.

해당 날짜0건은 완결된 상태다. `이 날짜의 일정이 없습니다`와 같은 월의 다음 일정으로 가는 경로를 제공한다. 필터 때문에0건이면 `표시 조건에 맞는 일정 없음`과 표시 설정 접근을 제공한다. 자료가 없는 상태와 필터 결과 없음, 서버 확인 실패를 같은 빈칸으로 처리하지 않는다.

좁은 너비에서는 월간 캔버스와 일간 패널을 무조건 병렬로 짜 넣지 않는다. 같은 창에서 날짜를 선택하면 일간 내용을 우선 표시하고 월로 돌아갈 수 있는 구조를 사용한다. 데이터 상세를 읽기 위해 별도 작은 창을 만들지는 않는다.

### 4. 전역 발표와 진행 중 자료

얼리/정식 출시의 발견성은 유지한다. 다른 달을 볼 때는 `주요 발표 · 얼리2/19 / 출시2/23` 같은 작은 바로가기가 유용하다. 해당2월을 볼 때는 월간 표식과 월내 agenda로 자연스럽게 읽히도록 하여 동일한 두 발표를 여러 큰 카드에서 반복하지 않는다. 사용자 요구는 출시를 놓치지 않도록 포함하는 것이며, 항상 같은 크기의 고정 카드를 유지하는 것은 기존 구현 선택이었다.

종료 미정 자료를 삭제하거나 기능을 없애지 않는다. `진행 중/기한 확인` 같은 보조 agenda에 접근할 수 있어야 한다. 확정 마감이 없는 혜택이 월간 계획보다 긴 면적을 차지하지 않도록 한다. 전장 정보는 이 단일 창 안의 낮은 높이 요약으로 유지한다. 기준 미확인은 한 번 명확히 설명하고 가짜 맵이나 날짜를 채우지 않는다.

## 일정 의미와 확실성의 표현

| 자료 의미 | 월간 기본 표시 | 일간/상세 표현 |
| --- | --- | --- |
| 한 시점의 출시·얼리·예선 | 해당 날짜의 점 표식 | 정확한 역할과 발표 정밀도의 날짜/시각 |
| 시작/종료가 알려진 기간 | 시작일·종료일 표식 | 전체 기간과 선택 날짜가 기간 안인지 표시 |
| 기간 막대 선택 | 연속 구간, 시작/끝과 이어짐 방향 | 같은 원본 기간, 날짜 해석은 바꾸지 않음 |
| 공식 조건으로 종료 | 날짜를 만들어 넣지 않음 | `8.0 점검 시작 전` 등 조건을 그대로 표시 |
| 시작은 과거, 종료 미발표 | 시작 날짜 이력과 진행 상태 보조 목록 | `종료 미발표`, 마지막 확인 날짜와 원문 |
| 시작 자체가 미발표 | 날짜 없는 대기 목록 | 무엇이 미발표인지 명시 |
| 공지 게시일 | 기본 숨김, 사용자 체크 시 표시 | 게시 시각을 실제 패치 적용 시각과 구분 |

Point의 End가 unknown인 것은 정상적인 점 일정이며 ‘종료 미정 행사’로 넣으면 안 된다. 오래된 시작일만으로 상시라고 단정하지 않는다. source에 상시가 명시되지 않은 경우에는 ‘종료 미발표’가 정확하다. 자유로운 note 문구에서 UI가 임의로 새 종료 조건을 계산하지 않는다.

시간 정밀도와 출처 상태는 별도 축이다. `2/23 시간 미발표`는 날짜 자체가 미정이라는 뜻이 아니다. `공식 조건 확정·종료 날짜 미발표`도 완전히 정보가 없는 경우와 다르다. 원문 변경으로 검토 대기라면 기존에 알려진 날짜를 마지막 확인 값으로 구분한다. 전역 최신 수집 시각 하나가 모든 항목을 동시에 검증했다는 인상을 주면 안 된다.

## 실제 자료로 검증할 두 흐름

### A. 2027년2월19일의 서로 다른 행동

번들에는 얼리 액세스 시작, CE 사전예약 종료, 예약 특전 대상 구매 종료가 같은 날에 있다. 현재 한 줄+2개 더 보기만으로는 가장 중요한 전환을 비교하기 어렵다.

1. 사용자가 년월 또는 발표 바로가기로2027.02에 이동한다. 선택 날짜는 그달 안에 있고 전역11월 상태가 남지 않는다.
2. 19일 셀은 `얼리`와 `예약 마감`처럼 행동이 다른 표식을 우선 보여 준다. 추가 항목 수를 표시한다.
3. 19일 또는 +N을 누르면 우측/동일 창 일간 목록이 그날의3개 기준을 모두 보여 준다. `18:00 얼리 시작`, `18:00 CE 사전예약 마감`, `18:00 특전 대상 구매 마감`을 식별할 수 있다.
4. 관련된 백은의 탐구자 자료라는 시각적 묶음은 가능하지만 원본 사건을 삭제·병합해 각 마감과 출처를 잃지 않는다. 특히 특전 **구매** 마감을 아이템 **수령** 마감으로 바꾸지 않는다. 날짜 정밀도/포함 규칙이 다른 원본을 임의로 같은 한 건으로 단정하지 않는다.
5. 얼리 행을 선택하면 시작 시각과 이용 권한 조건/공식 안내를 본다. 23일의 정식 출시 행은 날짜만 발표됐다는 차이를 보여 준다. 얼리 종료가23일이라고 만들어 넣지 않는다.

### B. PvP 보상을 놓치지 않으려는 현재 플레이어

번들의 시리즈12는9월8일 시작이며 종료는8.0 점검 시작 전 조건이다. 이전 시리즈11 보상 수령도 별도 phase다. 마법자판 난타전처럼 note에는 업데이트 전까지라고 쓰였으나 wire 경계는 unknown인 자료도 있다.

1. 사용자가 PvP 체크를 켠 채 진행 중/기한 확인 목록을 연다. 시리즈12의 종료 조건과 이전 보상 수령을 서로 다른 행동으로 볼 수 있다.
2. `점검 시작 전 · 날짜 미발표`로 표시한다.2월19일 얼리나2월23일 정식 출시를 종료 날짜로 대입하지 않는다.
3. 이전 보상 수령 행을 선택하면 공식 안내와 마지막 확인 근거로 이동한다. 플러그인이 보상 수령 여부를 아는 것처럼 완료 표시를 만들지 않는다.
4. 날짜가 추후 확정되면 기존 phase의 조건이 해결됐다는 상태 변화로 연결하고, 동일한 보상을 새 사건처럼 중복 생성하지 않는다. 구현 전까지는 기존 조건을 유지한다.
5. 진행 중 미발표 자료를 모두 사용자에게 긴급 경고하지 않는다. 사용자는 조건을 확인하고 스스로 준비할 수 있어야 한다.

## 구현 우선순위와 완료 기준

P0는 선택 날짜·보고 있는 월의 일관성, 완전한 일간 목록, 역할이 읽히는 표식, 모든 긴 자료의 제한된 스크롤 영역이다. 이 상태 모델을 먼저 고쳐야 시각적 정리가 의미를 갖는다. P1은 월간 목록을 날짜별 시작/마감 agenda로 바꾸고, 전역 발표와 진행 중 자료의 접근 경로를 분리하는 것이다. P2는 관련 캠페인의 검토된 표시 그룹과 개인화 우선순위다. 계정 상태를 모르는 자동 할 일/완료 추론은 범위에 넣지 않는다.

| 검증 과제 | 성공 기준 |
| --- | --- |
| 월간 탐색 | 휠/직접이동 후 선택 날짜가 보이는 월과 일치하거나 명시적 월 overview 상태이고 오래된 날짜의 상세가 남지 않음 |
| 2/19 비교 | hover 없이 세 기준의 역할·시각·조건에 도달하고 얼리와 구매 마감을 구분함 |
| 빈 날짜 | 일정 없음과 필터로 숨김, 수집 실패를 구분하고 회복 경로가 있음 |
| 일정 종류 숨김 | 달력/월간 목록/주요 항목이 같은 표시 기준을 따르며 원본과 알림 선택은 삭제되지 않음 |
| 조건부 종료 | 정식 출시일을 종료일로 대체하지 않고 원문 조건을 읽을 수 있음 |

| 게임 중 확인 | 플레이어가 지정한 날짜와 가까운 마감을 짧게 찾고 창을 닫는 과제를 실기로 수행. native geometry 통과를 이 사용성 검증의 대체물로 보고하지 않음 |

## 제품 상태 모델의 후속 QA

실제96건 번들을 사용하는 자동 검사16개를 추가해 CalendarModel61검사가 통과했다. 기존45개 필터·기간 표시·저장·원격 재시도 검사를 유지하고, 날짜 선택이 자동으로 첫 일정을 고르던 기대를 명시적인 일간 agenda 상태로 바꿨다.

추가 검사는2월19일의 세 경계와23일 출시를 모두 가진 월간 agenda, 날짜만/정확 시각의 구별, 명시적 마감 edge 선택, Month/Day/Undated에서 Event로 갔다 돌아오는 흐름, 월 이동의 stale 선택 제거, 일정0건인 날짜, 정상 point와 개인 만료의 미정 오분류 방지, 조건부 PvP 종료 보존, 검색/표시 조건 유지, 새 원본 수신 후 사용자 focus 유지, 선택 사건 철회 시 남은 일간 목록 복귀를 포함한다.

이는 동작 상태와 데이터 의미를 검증한 것이다. 위의 게임 중 탐색 시간·역할 오인·읽기 편의성 과제는 실제 화면 검증으로 별도 확인해야 한다.

현재 구현은 P0/P1의 상태 전환과 접근 경로를 적용했다. 진행·기한 미정 보기는 해당 이벤트의 모든 미정 phase를 각각 노출하고 시작·종료 원문 경계를 함께 표시한다. 조건형 마감/시작 미발표/장기 혜택의 독립 그룹과 관련 캠페인 통합 표현은 후속 설계 과제이며 이번 구현 완료로 주장하지 않는다. 좁은 월 화면에는 중복 월 agenda를 아래에 붙이지 않고 상단 ‘월 목록’으로 접근한다.
