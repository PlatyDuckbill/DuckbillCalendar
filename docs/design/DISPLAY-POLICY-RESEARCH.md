# 일정 노출 규칙 심층 검토와 구현

2026-11-13 · 0.2.1. 사용자 실기 화면과 연속 피드백을 기준으로 공개 원문, 번들 전체, 시간 계약과 반례를 대조했다. 자료를 더 넣기보다 선택한 날짜에 필요한 답을 짧게 보여주는 것이 목표다. 사용자가 확정한 원칙은 **그날의 직접 일정 우선 / 기간 중인 이벤트 기본 접기 / 펼쳐도 작은 보조 카드 / 개별 숨김과 복원**이다.

## 조사 범위

- 번들 공개 사건96건과 단계100개 전수 분류. 이벤트14, 게임 점검6, 패치·출시11, PvP 시즌1/시리즈1, 할인2, notice61이다. notice 중60건은 게시 시점만 있고1건은 실제 CCRC 단계다. 달력 정책 통과36건/40단계와 새소식 원본을 구분한다.
- 날짜 정밀도별8가지 조합: date→condition 1, date→date 3, date→instant 1, date→unknown 점 일정13, instant→instant 9, instant→unknown 기간11, instant→unknown 점 일정61, unknown→condition 1. 미정 끝을 점 일정과 장기 기간으로 혼동하지 않는다.
- 게임 점검 전후 공지, 패치노트, 예약·구매 혜택 표, 대회 단계, PvP 보상 조건의 공식 원문 재확인.
- 인지 부담·의미 있는 묶음·보조 정보 공개·색만으로 구분하지 않는 원칙을1차 가이드에서 확인. 아래 제품별 우선순위는 이 앱과 사용자 목적에 적용한 설계 판단이며 사용자 연구로 실증된 점수라고 주장하지 않는다.

## 정보 위계에 적용한 근거

필수 정보와 보조 정보를 나누고 펼칠 항목의 이름에서 내용을 예상할 수 있게 하는 원칙을 적용했다. ‘기간 중인 이벤트 N건’은 삭제나 불명확한 더 보기 대신 내용을 설명하는 한 단계의 보조 진입점이다. [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/).

일정 하나의 제목·기간·행동을 같은 카드 안에 둬 경계를 읽을 수 있게 했다. [Google의 containment 구성요소 가이드](https://developer.android.com/design/ui/mobile/guides/components/material-overview). 색 외에도 아이콘과 종류 이름을 함께 제공한다. [W3C의 색 사용 원칙](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html). 이 원칙의 적용을 완전한 WCAG 준수 인증으로 표현하지 않는다.

## 구현 규칙

`CalendarPresentation`은 원본 데이터를 바꾸지 않는 표시 투영이다.

1. 선택 날짜의 자료만 받고 같은 event+phase의 중복 edge를1개 표시 단위로 묶는다. 멤버에는 원본 edge 모두 남긴다.
2. 패치/점검은 구조화된 KR 버전 ID, 같은 날의 점검, 실제 공통 evidence ID, 확인 상태가 모두 맞고 후보가1개일 때만 묶는다.
3. 구매 캠페인은 원문으로 검토한3개 stable ID만 사용한다. 이름이나 URL 일부가 비슷한 새 행사를 자동으로 같은 캠페인으로 만들지 않는다. 다른 시작/마감, 다른 정확한 시각은 분리한다.
4. 숨김과 종류 필터는 투영 전에 적용한다. 같은 캠페인의 하나만 숨기면 남은 자료로 다시 표시한다. 단일/전체 복원은 설정에서 한다.
5. 직접 일정은 개인 계획 → 마감 → 서버 이용 영향/출시 → PvP → 대회 → 이벤트/구매 시작을 우선한다. 같은 급에서는 발표된 정확한 시각과 안정적인 식별자로 정렬한다. 이 순위는 긴급 알림이나 참여 자격 판단이 아니다.
6. 기간 중인 항목은 별도 분리하고 알려진 마감이 가까운 순으로 정렬한다. 기본 접고 매번 새 날짜를 열 때 접힘 상태로 시작한다. 펼친 카드는 작고 낮은 강조를 사용한다.
7. 고정 Top2/Top3를 두지 않는다. 칸의 픽셀 여유만큼 의미 단위를 보여주고 나머지는 날짜 옆 +N으로 연결한다. 같은 날짜 팝업에서는 직접 일정 전체를 볼 수 있다.

## 검증과 남은 한계

실제96건과 합성 반례로 멤버·edge의 완전 보존, 공통 근거 없는 동일 버전, 다른 버전, 복수 점검, 밤샘, 재검토/예정/확인도 없음, 같은 제목의 별개 행사,1분 차이 구매 마감, 개인 계획 우선, 숨긴 멤버 누출, 다른 날짜 입력을 검사한다. native UI는 실제 날짜/메뉴/숨김/보조 영역/미니 달력 클릭과 시각 문자 입력을 검증한다. 재시작 저장/개별 복원/전체 복원도 확인한다.

이것은 발표 자료의 계약과 현재 번들에 대한 깊은 검토다. 미래의 모든 게임 이벤트를 자동 이해하는 의미 모델은 아니다. 새 캠페인은 명시적 관계를 검토하기 전에는 별개로 표시하는 보수적인 기본값을 따른다. 사용자의 구매·참여·보상 수령 여부는 수집하지 않는다. 게임 GPU·실제 폰트/DPI·사용자 과제 수행은 다시 게임에서 확인해야 한다.
